# Reporting a security problem

Please keep vulnerability details, exploit instructions, credentials and private
installation data out of public issues.

If the repository's **Security → Advisories** page offers **Report a vulnerability**,
use that form for a private report. If private reporting is unavailable, open a
public issue asking only for a private security contact, without describing the
vulnerability. Share the details after a private channel has been agreed.

A useful private report includes the exact bridge/image version, affected
component, impact and minimal reproduction using synthetic values. Do not send
real passwords, tokens, authenticated API captures or complete state backups.

For ordinary setup problems and reproducible bugs, use
[GitHub issues](https://github.com/alaub81/sma-mqtt-bridge/issues) and the
[troubleshooting guide](docs/OPERATIONS.md#common-setup-problems).

See [GitHub's private reporting guidance](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately)
for the reporting workflow and availability requirements.
